# TruthPass Agent-first 厂家直销闭环

## 一句话

TruthPass 不是替厂家写一页宣传文案，而是把一件商品从生产、检测、运输到购买后的反馈，绑定到同一个批次记录；用户的 Agent 负责读取和解释，确定性规则负责核对，钱包负责身份和签名，区块链负责保存可复核的摘要与事件。

首个闭环：鱼油 `FO-2026-001`、BOT Chain `677`、外部非托管钱包。当前生产和检测资料仍是 `demo/synthetic`，真实验收首先证明支付、receipt、购买绑定、反馈绑定和审计链路。

## 用户看到的流程

```text
扫码 / 输入批次
→ Agent 读取当前批次资料
→ 展示生产、检测、冷链和售后参数
→ 显示来源、签名、缺口、冲突和规则范围
→ 给出有限范围的推荐或复核建议
→ 用户选择购买
→ 钱包确认支付
→ 服务端核验 receipt 和业务事件
→ 生成购买凭证
→ 用户反馈绑定同一批次
→ Agent 汇总反馈，形成厂家改进建议
```

Agent 的推荐只能是三种状态：

```text
recommend_with_scope          资料充分，说明适用范围后推荐
review_before_recommendation   关键资料缺失或冲突，先复核
do_not_recommend               确定性规则失败，停止推荐
```

## 必接入的数据

| 数据域 | 必要字段 | 主要来源 | 核对方式 |
|---|---|---|---|
| 批次和生产 | tenantId、productId、batchId、生产时间、数量、原料批次 | 生产方系统/企业 Agent | 服务端批次绑定、时间和数量一致性 |
| 检测 | sampleId、检测方法、指标值、单位、报告、机构签名 | 检测机构 | issuer 公钥、签名、报告批次、样品绑定、规则范围 |
| 冷链物流 | 设备 ID、时间序列、温度/湿度、异常区间、交接人 | 物流设备/物流方 | 设备签名、时间连续性、批次交接、异常重叠 |
| 包装与出货 | 包装版本、数量、出库时间、运输单 | 生产方/物流方 | 数量对账、批次一致、重复媒体 Hash |
| 购买 | quoteId、wallet、batchId、price、txHash、receipt | 消费者钱包 + 服务端 | Chain ID、目标合约、发送者、金额、事件和 batchId |
| 反馈售后 | purchaseId、评分、类别、反馈 Hash、贡献 txHash | 消费者钱包 | 购买凭证、一次性约束、反馈 Hash 和贡献事件 |
| 争议复核 | finding、证据引用、机构签名、裁决 | 审核/仲裁机构 | 角色授权、证据白名单、状态机和审计记录 |

原始报告、订单详情、个人地址和健康信息留在链下。公开层只返回聚合结果和必要的证据摘要。

## 每条数据如何核对

```text
1. 身份：issuer / wallet 是否属于声明角色
2. 范围：tenantId、productId、batchId、evidenceId 是否同域
3. 完整性：contentHash、媒体 Hash、报告 Hash 是否匹配
4. 新鲜度：occurredAt、sequence、nonce 是否连续且未重放
5. 规则：Verifier 用服务端 policy 计算，不接受 Agent 自报结果
6. 路由：JEV 只能选择补证、复核或继续，不能升级核验状态
7. 解释：模型只能引用白名单证据和 chainContext
8. 写入：钱包签名后，服务端读取 receipt 并逐字段核对事件
```

“代码校验通过”只表示结构、来源 ID 和状态边界通过；它不证明链下来源本身真实，也不证明商品质量或疗效。

## 区块链真正发挥的作用

区块链适合保存：

- 证据根、版本、签名和撤销/替代关系；
- 机构确认、购买凭证和消费者反馈贡献事件；
- 交易发送者、目标合约、金额、Chain ID 和 receipt 状态；
- 可被第三方复核的时间顺序和不可抵赖摘要。

区块链不自动解决：

- 生产方是否在链下提交了真实资料；
- 检测机构是否诚实；
- 设备是否被篡改；
- 模型是否理解事实；
- 商品是否适合某个具体人的健康需求。

因此公开状态必须区分：

```text
demo/synthetic             演示资料
replay_verified            历史回放已验证
anchor_pending              已生成计划，等待签名或 receipt
mainnet_receipt_verified    当前真实 receipt 和业务事件均已核验
```

## 厂家直销和 Agent 参与生产

这是一种“厂家 → 消费者”的直接关系，但不是让 Agent 自己付款或替厂家承诺质量：

```text
厂家提交资料 → Agent 整理缺口 → 规则核对 → 机构确认
→ 厂家发布批次页 → 消费者 Agent 解释 → 消费者钱包购买
→ 购买后反馈 → 厂家看到按批次聚合的问题 → 企业确认改进任务
```

用户 Agent 参与生产的含义是：它把消费者真实使用、保存、包装、物流和售后反馈，回写到批次和产品改进建议；最终改进任务仍需厂家确认，不能由模型直接改变生产状态。

## 安全耦合条件

设当前批次证据集合为 `E(B)`，确定性结果为 `V(B)`，链上摘要为 `C(B)`，则必须满足：

```text
引用(M) ⊆ E(B) ∪ 公开来源
JEV(M) 不得改变 V(B)
receipt(B) ⇒ sender、contract、chain、amount、event、batch 全匹配
feedback(B) ⇒ purchaseId(B) 且一次购买只能贡献一次
revoked(E) ∉ E(B) 的可引用集合
```

任何条件失败，Agent 只能输出缺口、复核或等待确认，不能输出“已认证”“已购买”“已上链”。

## 真实试点的最小闭环

```text
1 个真实生产方
1 个真实检测机构
1 个真实批次
1 个消费者外部钱包
1 笔 0.001 BOT 购买
1 个可核验 purchase receipt
1 次购买后反馈和贡献 receipt
1 份厂家改进报告
```

在这组证据完成前，鱼油页面只能称为演示闭环，不能称为真实商品认证。

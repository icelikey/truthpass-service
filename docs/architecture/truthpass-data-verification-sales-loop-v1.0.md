# TruthPass 数据、核对、上链与直销闭环 v1.0

## 目的

TruthPass 的产品不是“给商品贴一个已验证标签”，而是把一件商品从生产资料、检测结果、运输记录到消费者购买和反馈，组织成一个可追溯的事实网络。Agent 负责读取和解释，Verifier 负责确定性比较，JEV 负责决定下一步路由，钱包负责身份和签名，区块链负责保存摘要、签名、事件和交易回执。

页面中的质量信息统一使用四个词：

- **实测值**：来源记录中的数值或状态；
- **当前规则范围**：绑定到版本化 policy snapshot 的比较范围；
- **差值/缺口**：实测值距离范围的差异，或尚未登记的资料；
- **下一步**：补资料、复核、签名或继续观察。

“在当前规则范围内”只描述登记资料与当前规则的比较结果，不表示真实商品认证、安全或疗效。`demo/synthetic` 始终标注为演示资料。

## 1. 首个鱼油闭环

```text
生产方提交批次资料
  → 资料标准化、Hash、绑定 tenant/product/batch
  → 检测机构提交报告和样品关系
  → 物流设备提交温度、时间和运输事件
  → Verifier 读取固定 policy snapshot，输出实测值、规则范围、差值和缺口
  → JEV 选择继续解释、补资料、复核或拒绝
  → 企业和机构钱包确认责任
  → 链上保存证据根、policy hash、签名和事件摘要
  → 消费者 Agent 解释当前批次，并给出有范围的购买建议
  → 消费者钱包付款/签名，服务端校验 receipt
  → 生成购买凭证和批次绑定
  → 消费者反馈先绑定购买凭证，再形成反馈 Hash 和贡献事件
  → 企业 Agent 汇总反馈，生成待确认的生产改进建议
```

首个演示批次是 `FO-2026-001`，数据模式为 `demo/synthetic`。这条链路可以验证系统的绑定、路由、解释和审计能力，但不能替代真实生产方、检测机构和物流设备的正式资料。

## 2. 需要接入的数据

| 环节 | 最小字段 | 可信来源 | 服务端核对 | 对外展示 |
| --- | --- | --- | --- | --- |
| 生产 | 批次号、原料批次、产地、生产时间、配方/工艺版本、设备事件 | 生产方系统或授权采集设备 | 字段 schema、批次关系、时间顺序、来源签名 | 生产事实和覆盖状态 |
| 检测 | `sampleId`、报告号、检测方法、单位、EPA+DHA、PV/AV、p-Anisidine、TOTOX、重金属、报告时间 | 具备登记身份的实验室 | 报告批次匹配、方法/单位匹配、签名和有效期、数值范围 | 实测值、规则范围、差值、报告来源 |
| 冷链 | 设备 ID、采样时间、温度/湿度、异常区间、运输单号 | 物流方或平台设备 | 设备绑定、时间连续性、异常区间、签名/Hash | 覆盖时间、异常时长、缺口 |
| 仓储/出货 | 入库、货位、出库、数量、时间、单据关系 | 企业/仓储系统 | 数量守恒、批次绑定、时间逻辑 | 仓储和出货记录 |
| 购买 | `quoteId`、钱包地址、金额、目标合约、Chain ID、txHash、receipt、事件 | 外部钱包和链节点 | 发送者、目标、Chain ID、金额、状态、业务事件和 batchId | 购买状态和凭证 |
| 反馈 | `purchaseId`、购买 txHash、钱包证明、评分、分类、反馈 Hash、贡献 txHash | 已购买消费者 | 一次购买一次反馈、Hash、授权和 receipt | 只展示聚合统计 |

原始报告、原始评论、订单详情、个人地址和健康信息留在链下。链上只放可验证的摘要和事件引用。

## 3. 参数核对模型

设一条证据为：

```text
e = (tenantId, productId, batchId, evidenceId, issuerId,
     sourceKind, occurredAt, contentHash, signature, dataMode)
```

设版本化规则为 `π`。以鱼油为例，参数比较不是一个模糊的 `passed`，而是：

```text
EPA+DHA:       x >= π.minEpaDhaPercent
过氧化值:       x <= π.maxPeroxideValue
TOTOX:          x <= π.maxTotox
冷链异常时长:    x <= π.maxLogisticsGapHours
重金属:         Pb/Hg/Cd/As 分别与各自限值比较
```

每个比较返回：

```json
{
  "key": "peroxide",
  "observed": 6.8,
  "unit": "meq/kg",
  "rule": "<= 5 meq/kg",
  "difference": -1.8,
  "status": "outside_range"
}
```

`missing` 表示没有登记实测值，不能被改写成 `outside_range`；`outside_range` 只表示该登记值与所选规则范围的比较结果。规则范围来自 policy 的版本和来源，不能由模型或前端修改。

确定性结果的简化表达是：

```text
P(e, π) = identity_binding
        ∧ signature_valid
        ∧ batch_relation_valid
        ∧ time_order_valid
        ∧ all_required_values_present
        ∧ every_parameter_in_range
```

其中任意一项未知都应保留为 `missing/review`，不能被模型补成通过。代码校验只能证明输入满足程序条件，不能证明生产方提交的原始事实本身真实；事实真实性仍依赖签发方、设备、抽样、实验室和复核机制。

## 4. 区块链到底证明什么

链上提交的是一个承诺：

```text
C = H(tenantId, productId, batchId,
       evidenceRoot, policyHash, verificationResultHash,
       issuerSignatures, eventType, nonce)
```

区块链可以证明：

1. 某个摘要在某条链、某个合约、某个区块中被提交；
2. 指定钱包是否签了指定操作；
3. 交易是否有真实 receipt、状态和业务事件；
4. 后续读到的批次摘要是否与已锚定摘要一致；
5. 事件是否按 nonce/幂等键只被记录一次。

区块链不能单独证明：

1. 传感器没有被篡改；
2. 实验室样品一定代表整批商品；
3. 企业提交的原始数字一定真实；
4. 商品一定安全、有效或适合某个个体；
5. Agent 的自然语言结论天然正确。

因此页面上应把链状态单独显示为 `replay_verified`、`anchor_pending` 或 `mainnet_receipt_verified`，不要把它写成商品质量结论。

## 5. 厂家直销和消费者 Agent 的真实含义

“厂家直销”在系统里不是把销售页面换成 Agent，而是让交易对象和责任链直接绑定：

```text
企业发布可核对批次
  → 消费者 Agent 读取同一批次资料
  → 消费者选择购买并由自己的钱包签名
  → 付款进入配置的商家收款路径
  → receipt 校验后生成 purchaseId
  → 购买凭证绑定 batchId
```

Agent 可以根据已核对的生产、检测、物流和反馈资料回答“为什么推荐/为什么需要复核”，但不能代替消费者付款、机构签名或修改规则。推荐契约应只允许：

```text
recommend_with_scope
review_before_recommendation
do_not_recommend
```

消费者反馈不是营销评论，而是生产闭环的一条新证据：只有已核验购买才能提交，服务端保存反馈 Hash 和贡献回执，公开层只返回聚合结果。企业看到的是“某批次哪些环节反复出现问题”，再由企业确认是否创建生产改进任务。

## 6. 关键风险和控制

| 风险 | 可能后果 | 控制和验收 |
| --- | --- | --- |
| 企业或设备提交假数据 | 链上永久保存错误摘要 | 来源签名、设备密钥、抽检、机构复核；链上不可替代现实取样 |
| 跨批次/跨租户引用 | Agent 得出错误推荐 | 所有证据绑定四元组，服务端白名单校验，错配直接拒绝 |
| 缺失资料被当成失败或通过 | 用户误判 | `missing` 与 `outside_range` 分开，缺口显示责任方和下一步 |
| 模型编造数字或交易结果 | 错误下单、虚假上链 | 严格 JSON、引用白名单、数值守卫、receipt 成功词拦截、确定性 fallback |
| 回放交易冒充当前交易 | 虚假购买证明 | 回放只显示 `replay_verified`，当前购买必须有对应 receipt 和事件 |
| 机构密钥泄露/越权 | 伪造检测或审核 | 钱包角色绑定、密钥轮换、撤销、服务端验签和审计 |
| 反馈刷量或重复提交 | 改进报告失真 | `purchaseId` 一次一次反馈、贡献交易幂等、聚合不公开个人映射 |
| RPC 不可达 | 页面误报已上链 | `rpcReachable=false` 时只能显示待确认/不可读取，不显示成功 |
| 链上隐私泄露 | 购买和个人关联暴露 | 链上只放摘要，订单和原始反馈链下，公开只读聚合 |

## 7. 当前版本的边界

当前仓库已经具备参数化展示、确定性 Verifier/JEV、证据引用、钱包准备和支付适配的代码路径；本地回归为 190/190。首个鱼油批次仍是 `demo/synthetic`，所以当前能证明的是协议和软件行为，不是生产事实和真实商品认证。下一步的真实放行证据必须包括：厂家/实验室/物流签名资料、真实 Chain 677 receipt、购买绑定、反馈贡献 receipt，以及从同一 `tenantId/productId/batchId` 读回的审计记录。

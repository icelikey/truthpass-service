## 1. 项目目标

### 1.1 比赛目标

用一个可现场操作的鱼油批次 Demo 证明：当 Agent 面对陌生检测、冷链或供应服务时，不能只看链上身份和历史分数，而应先探测当前状态，再验收本次交付，并把结果变成下一个 Agent 可以复用的公共信息。

### 1.2 产品目标

鱼油提供一个容易理解、指标可量化、痛点足够明显的场景：标签含量、氧化、新鲜度、重金属风险、批次对应关系和冷链中断都可以转成结构化验收条件。消费者不是被动看溯源页面，而是在购买后通过自己的 Agent 授权提交最小化反馈，参与批次信誉维护。

### 1.3 不做的事情

- 不做降血脂、预防疾病等医疗功效判断；
- 不读取或上链消费者健康档案；
- 不把模拟数据描述成真实实验室证明；
- 不在比赛 MVP 中发行股权、分红或可交易代币；
- 不做完整商城、支付、跨链和复杂 DAO。

## 3. 总体架构

```text
用户/消费者 Agent
        │ 自然语言意图、购买证明、授权反馈
        ▼
语义适配层（API / Skill / MCP）
        ▼
真验编排层
  Planner → Discovery → Probe → Router
        │                         │
        ▼                         ▼
  证据标准化层              服务注册与历史信誉
  Lab Agent / ColdChain Agent / Supplier Agent
        ▼
确定性 Verifier
  批次、时间、签名、EPA+DHA、氧化、冷链、证据完整性
        ▼
证据卡 + 任务履约反馈 + 争议状态
        ├── 链下：报告、图片、传感器明细、隐私数据
        └── 链上：身份、时间、结果、任务哈希、证据哈希、撤销事件
```

### 3.1 Agent 边界

- `Planner Agent`：把“我要买高浓度且新鲜的鱼油”转成结构化门槛；
- `Discovery Agent`：从注册表找候选检测、冷链和供应服务；
- `Probe Agent`：调用 `health`、`capabilities` 和小型挑战；
- `Evidence Agent`：把 COA、标签、冷链摘要和图片标准化；
- `Verifier`：只用可复现代码做通过、拒绝或部分完成判断；
- `Router Agent`：优先选择当前可用、能力匹配且本次验收得分高的服务；
- `Reputation Agent`：生成反馈、聚合近期履约并提交链上锚定。

大模型可以解释“为什么拒绝”，但不能直接覆盖规则结果、写入信誉或替消费者授予健康结论。

## 4. 核心数据合同

### 4.1 任务请求

```json
{
  "taskId": "task-fish-oil-2026-001",
  "serviceKind": "lab",
  "capability": "fish-oil-batch-quality-check",
  "batchId": "FO-2026-001",
  "productionTime": "2026-10-06T08:00:00Z",
  "acceptance": {
    "requireSignature": true,
    "minEpaDhaPercent": 70,
    "maxPeroxideValue": 5,
    "maxTotox": 20,
    "maxLogisticsGapHours": 6,
    "requireColdChain": true
  }
}
```

### 4.2 证据摘要

```json
{
  "batchId": "FO-2026-001",
  "reportBatchId": "FO-2026-001",
  "epaDhaPercent": 78,
  "peroxideValue": 2.1,
  "totox": 11,
  "coldChainGapHours": 2,
  "signatureValid": true,
  "payload": { "evidenceMode": "demo/synthetic" }
}
```

完整报告通过对象存储或数据库保存，摘要中只保留访问控制后的 `reportHash`、`evidenceHash` 和签名信息。

## 5. 验收和评分

### 5.1 硬失败条件

以下任一项失败，结果直接为 `rejected`：任务或批次不匹配、签名无效、关键指标超过门槛、冷链证据缺失或超过允许中断时间。

### 5.2 服务排序

```text
服务总分 = 历史履约 25% + 当前可用性 20% + 本次验收 55%
```

评分只用于候选排序，不能掩盖硬失败。历史评分应按时间衰减，撤销记录和同一任务重复反馈不计入聚合。

### 5.3 公共信誉内容

公共记录至少包含：服务 ID、服务类型、任务哈希、证据哈希、验收状态、评分、创建时间、撤销状态、反馈来源类型（检测/冷链/消费者）。不公开消费者姓名、地址、手机号、订单全文或健康数据。

## 6. 消费者参与闭环

```text
消费者购买
  ↓
授权 Agent 读取 purchase / packaging / odor / storage / quality-feedback 范围
  ↓
购买记录绑定批次和购买证明哈希
  ↓
提交一次性体验反馈并附证据哈希
  ↓
规则校验：已购买、已授权、未重复、评分范围正确
  ↓
贡献积分、复检优先权或服务额度
  ↓
反馈事件可写入公共信誉
```

消费者参与的是“证据复核和公共信誉共建”，不是未经资质授权的实验室检测。未来可以增加复检投票、争议发起和早期共建者权益；比赛版本只演示积分和服务权益。

## 7. API 最小集合

```text
GET  /services?kind=lab&capability=fish-oil-batch-quality-check
POST /services/:id/probe
POST /tasks/inspect
GET  /batches/:batchId/evidence-card
POST /consumer/consents
POST /consumer/purchases
POST /consumer/feedback
GET  /reputation/services/:serviceId
POST /chain/anchor
```

所有写接口要求 `requestId`，返回 `evidenceHash` 或 `feedbackId`，并支持幂等重试。Agent 不应直接访问数据库或合约私有方法，只调用经过校验的工具层。

## 8. 开发阶段和门禁

### 阶段 A：冻结合同（0.5 天）

冻结任务、证据、反馈和消费者授权 JSON；确认状态机为 `discovered → probed → executed → verified → anchored`，异常进入 `rejected` 或 `disputed`。

门禁：队友提交接口样例，架构负责人逐字段审查。

### 阶段 B：核心规则（0.5 天）

实现服务注册、探测、验收、反馈、防重复和消费者参与内存实现；运行仓库测试。

门禁：批次错、服务离线、签名错、EPA+DHA 低、过氧化值高、冷链超时都必须得到可解释拒绝。

### 阶段 C：Agent 和数据适配（1 天）

接入队友的 Agent 编排、数据库、向量召回和报告上传。向量库只做相关证据召回，不能替代验收规则。

门禁：同一任务可重放；规则结果不因大模型措辞变化而变化；服务失败可切换候选。

### 阶段 D：前端证据卡（0.5 天）

实现批次搜索、实时服务状态、检测指标、冷链时间轴、证据来源、公共反馈和消费者反馈表单。

门禁：用户在 90 秒内能看懂“为什么通过/拒绝”和“哪些数据仍是厂商自报”。

### 阶段 E：链上锚定（0.5 天）

部署最小 `TrustRegistry` 到测试网络或使用本地模拟；将服务注册、履约反馈、消费者购买和贡献事件写成交易摘要。

门禁：交易失败不影响链下验收；重复提交不会产生重复反馈；链上事件能回溯到链下证据哈希。

### 阶段 F：比赛演练（0.5 天）

完整演练“查询 → 探测 → 失败候选 → 成功候选 → 证据卡 → 消费者反馈 → 链上锚定”，录制备用视频并准备离线数据。

门禁：网络断开时仍可展示离线证据卡；不把模拟数据说成真实检测；所有演示按钮有明确反馈。

## 9. 风险与应对

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 商家自报数据造假 | 错误信任 | 标注来源等级；要求第三方签名和多源交叉验证；链上只证明提交事实 |
| 服务刷分/女巫 | 信誉失真 | 反馈绑定任务/购买；一次性约束；时间衰减；后续加入质押和身份关联分析 |
| 传感器被替换 | 温度或视频不可信 | 设备身份、批次绑定、nonce、连续性校验；异常转人工复检 |
| LLM 幻觉 | 误判或越权 | 规则引擎决定结果；LLM 只规划和解释；工具层白名单 |
| 隐私泄露 | 消费者风险 | 最小授权、哈希上链、原文链下、可撤销授权、默认匿名 |
| 鱼油合规表述过度 | 路演风险 | 只讲质量、新鲜度和证据，不讲治疗效果；展示“检测结论”而非“健康保证” |

- [ ] 链上只锚定哈希和状态，不上传个人信息和报告原文；
- [ ] 现场网络失败时有离线演示数据和录屏备份。

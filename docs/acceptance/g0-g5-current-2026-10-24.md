# TruthPass G0-G5 可持续验收总表（2026-10-24）

## 结论

本次本地版本已经可以运行一条**安全回退的 Agent 只读链路**：

```text
批次总览 → Verifier → JEV → 确定性回答 → SSE 阶段和证据引用
```

当前不能称为真实闭环。真实模型、真实钱包签名、BOT Chain 677 receipt、购买凭证和反馈上链仍需要外部环境配置与用户钱包确认。

请求：

```powershell

curl.exe -sS -N -X POST http://127.0.0.1:4173/api/agent/chat `
  -H "content-type: application/json" `
  -H "x-truthpass-request-id: probe-local-20261024-001" `
  --data-raw $payload
```

SSE 阶段顺序已观察到：

```text

```

chainContext.transaction: null

回答明确说明生产资料只覆盖 `2/7` 个阶段，并提示当前资料不能替代真实商品认证。

## G2：真实模型验收方法（当前待配置）

Vercel Production/Preview 只允许在服务端加密变量中配置，不得写入仓库或前端：

```text
AGENT_PROVIDER=opencode      # 或明确选择 deepseek/compatible
OPENCODE_API_KEY=[REDACTED_SECRET]
OPENCODE_BASE_URL=https://...
OPENCODE_MODEL=...
```

配置后必须同时保存以下证据：

1. `GET /api/agent/status`：`providerConfigured=true`；
2. 一次 `POST /api/agent/chat` SSE 原文：`modelAssisted=true`；
3. `meta.provider/model` 与 status 的 configured/lastSuccessful 字段一致；
4. `traceId`、`batchId`、`evidenceIds` 全部属于同一次请求；
5. 将模型变量移除或让 provider 超时，重新请求并证明 `validationStatus=fallback`，且回答仍包含当前批次缺口和下一步。

只看到 `providerConfigured=true` 或 HTTP 200 不算真实模型调用证据。

## G3：钱包与链上验收方法（当前未放行）

必须由用户在钱包中明确确认测试网络/金额后执行：

```text
连接外部钱包 → 读取 Chain ID 677 → prepare → 钱包签名 → 广播 → receipt 读取
```

服务端必须逐项回读：

```text
sender == 用户钱包地址
target == 配置的 Paid Consumer Gateway
chainId == 677
value == 报价金额
PurchaseRecorded 事件存在
PaymentReceived 事件存在
batchId / purchaseId 与报价一致
receipt.status == 1
```

状态规则：

```text
无 receipt                 → anchor_pending
receipt.status != 1       → receipt_failed / review_required
事件或上下文不匹配          → review_required
全部匹配                   → mainnet_receipt_verified
```

只有最后一种状态可以显示“购买已确认/支付已核验”。历史回放只能显示 `replay_verified`。

## G4：购买、反馈和企业改进验收方法（当前未放行）

顺序不能跳过：

```text
mainnet_receipt_verified
→ purchaseId
→ POST /api/feedback/prepare
→ 消费者钱包签名 contribution
→ POST /api/feedback/confirm
→ GET /api/feedback/summary?batchId=FO-2026-001
→ GET /api/tenants/{tenantId}/production-improvement-report
```

必须验证：

```text
feedback.purchaseId == 已核验购买 purchaseId
feedback.purchaseTxHash == 已核验购买 txHash
同一 purchaseId 不能重复提交
contribution receipt 的 batchId/purchaseId/evidenceHash 匹配
公开汇总只有 count、评分和类别聚合，不泄露个人信息
企业报告只读取当前 tenant/batch
```

## 当前放行判定

|---|---|---|

## 安全边界

- Agent 解释证据，不修改确定性核验结果；
- Verifier/JEV、模型、钱包、链上 receipt 各自承担不同责任；
- `demo/synthetic` 不可升级为真实认证；
- 代码校验通过只表示契约和引用约束通过，不表示事实已经被代码证明；
- 不在日志、截图、文档或提交中记录 API Key、私钥、支付凭据。

# 真验私链构筑蓝图

> 文档版本：v0.8.4  
> 状态：当前战略方案；私链尚未建设  
> 最近修改：2026-10-07  
> 修改摘要：解释 BOT Chain 的运行逻辑，定义 TruthPass 联盟链的职责、节点、数据边界、公共锚定方式和分阶段建设门槛。  
> 影响范围：BOT Chain、链下证据仓、Agent、JEV、确定性 Verifier、CLI、鱼油 Demo、生产部署  
> 队友下一步：继续使用现有 BOT Chain Demo；不要把本方案中的联盟链节点、私链合约或生产能力写成已完成。

## 1. 先说结论

当前已经运行的是一条真实的 BOT Chain Bohr Testnet 公链，TruthPass 合约部署在这条链上。它记录的是证据承诺、验收结果、购买承诺、贡献、争议和替代关系；它不保存鱼油原始报告、设备时序、图片或消费者个人信息，也不能单独证明现实数据一定真实。

当前最适合 TruthPass 的方案不是立即自建一条链，而是：

```text
链下证据仓 + Agent/Verifier + BOT Chain 公共锚定
```

当多个厂家、实验室、物流方和复核方需要共享内部事件，又不愿把原始数据公开时，再建设一条由多方共同维护的许可联盟链：

```text
生产/检测/物流数据
        ↓
链下证据仓（原文、图片、遥测、隐私数据）
        ↓
Agent + JEV 路由 + 确定性 Verifier
        ↓
TruthPass 联盟链（未来建设：事件承诺和内部审计）
        ↓ 只提交批次根/检查点
BOT Chain（当前已部署：公共锚定和跨方复核）
        ↓
消费者 Agent / CLI / 网页观察台
```

私链不是为了替代 BOT Chain，也不是为了把所有数据再存一份；它解决的是成员间的隐私、吞吐、权限和内部审计问题。

## 2. 当前 BOT Chain 是怎样运作的

### 2.1 一笔“鱼油证据”从哪里到哪里

以批次 `FO-2026-001` 为例：

1. 生产系统、实验室、冷链设备或人工复核产生原始资料；
2. 接入层把资料整理成 `EvidenceEnvelope`，记录批次、来源、时间、序列、schema、原文哈希和签名；
3. 厂家 Agent、实验室 Agent、设备 Agent 或冷链 Agent 负责提交和关联证据；
4. JEV 只识别缺口、冲突和下一步路由，例如“需要独立实验室复检”，不直接把结果判为合格；
5. 确定性 `Verifier` 按产品规则检查 EPA+DHA、过氧化值、TOTOX、冷链、批次一致性和签名；
6. Verifier 产生 `evidenceRoot`、`resultHash`、`policyHash` 和 `verifierVersionHash`；
7. 具有 `EVIDENCE_WRITER_ROLE` 或 `VERIFIER_ROLE` 的钱包提交合约交易；
8. 合约校验链 ID、EIP-712 域、角色、非空承诺、依赖关系和幂等性；
9. 交易被打包进 BOT Chain 区块，receipt 和事件成为公共可复核记录；
10. 消费者 Agent 通过 CLI 查询证据根、验收状态、争议和替代记录，再用自然语言解释给消费者。

### 2.2 当前合约具体记录什么

`TruthPassEvidenceAnchor` 当前的主要事件关系是：

```text
EvidenceAnchored
        ↓ evidenceRoot 已存在
VerificationRecorded
        ↓ 消费者完成购买承诺
PurchaseRecorded
        ↓ 一次购买只能形成一次贡献
ContributionRecorded
        ↓ 出现争议
DisputeRaised
        ↓ 追加替代或撤销，不删除历史
RecordRevokedOrSuperseded
```

当前合约的关键保护包括：

- `DEPLOYED_CHAIN_ID` 和 `DOMAIN_SEPARATOR` 防止把一笔交易静默重放到错误的链或错误的合约；
- 角色控制写入责任，Agent 本身不直接拥有所有写权限；
- 相同 request ID 只能重复提交完全相同的内容，内容不同会失败；
- 相同 `evidenceRoot` 不能被不同 request 重复占用；
- 验收必须引用已经锚定的证据根；
- 贡献必须引用已登记购买，且每次购买只接受一条贡献；
- 争议和撤销采用追加事件，历史记录不被删除。

当前测试网部署信息：Chain ID `968`，RPC `https://rpc.bohr.life`，合约地址 `0xCc836EF2606a1E75473D3E5e6fa2E6fBF4F0478e`。这证明的是测试网合约和事件生命周期已经跑通，不等于真实厂家数据已经完成生产认证。

### 2.3 BOT Chain 能证明什么，不能证明什么

它能证明：

- 某个授权地址在某个时间提交了某个承诺；
- 这份承诺对应哪个批次、schema、规则版本和验收结果；
- 购买、消费者贡献、争议和替代记录有没有被追加；
- 其他 Agent 可以用公开事件和链下证据哈希复核同一条历史。

它不能单独证明：

- 设备没有被替换或篡改；
- 实验室一定独立且校准有效；
- 样品交接过程中没有被调包；
- 厂家提交的原始资料一定是真实的；
- “链上通过”自动等于政府或第三方机构的法律认证。

所以真正的信任来自“来源签名、样品交接、批次绑定、检测资质、确定性规则、独立复检和公共不可静默修改记录”的组合，而不是来自区块链单独背书。

## 3. 你的私链应该是什么

### 3.1 不建议的定义

不要把私链理解成：

- 厂家自己运行一条链，然后自己决定什么能上链；
- 把所有生产原文和消费者数据复制到链上；
- 再部署一套与 BOT Chain 没有对账关系的“平行事实”；
- 让消费者必须运行节点或持有代币才能查询产品。

这种设计会把原来的信任问题换成“谁控制私链”的问题。

### 3.2 推荐定义

TruthPass 私链应是 **许可型联盟链**，由互相制衡的参与方共同维护：

| 参与方 | 主要职责 | 是否建议作为验证节点 |
| --- | --- | --- |
| TruthPass 运营方 | 维护协议、索引和公共锚定 | 是 |
| 厂家/品牌方 | 提交生产和批次证据 | 可作为成员，初期不单独控制多数节点 |
| 独立实验室或检测机构 | 提交检测报告和复检结果 | 是 |
| 物流/冷链服务方 | 提交运输和温度事件 | 可作为成员 |
| 质量复核/仲裁方 | 处理争议、撤销和替代 | 是 |
| 消费者 | 查询、授权购买和提交反馈 | 不运行验证节点，使用 CLI/公开读接口 |

联盟链中的“共同维护”比“厂家自证”更重要。单一厂家不应控制超过共识所需的多数验证权。

## 4. 推荐的技术构筑

### 4.1 链的实现

第一版联盟链推荐使用 EVM 兼容的 Hyperledger Besu 私有网络和 QBFT 共识：

- 可以继续使用 Solidity 合约和 EVM 工具链；
- 允许配置许可节点和成员账户；
- QBFT 适合固定成员、需要确定性最终性的联盟网络；
- 节点可以通过 JSON-RPC 接入现有 `src/chain.ts` 的适配方式。

Besu 官方私有网络文档提供 QBFT genesis、节点启动和节点 allowlist 的配置方式，可作为后续工程实施依据：[Besu private networks](https://besu.hyperledger.org/private-networks)。当前仓库没有创建 Besu 网络，也没有把它宣称为已部署能力。

### 4.2 节点数量和治理

试验环境至少使用 4 个验证节点，生产试点优先使用 7 个节点：

```text
Node-1 TruthPass 运营方
Node-2 独立实验室 A
Node-3 物流/冷链方
Node-4 质量复核方
Node-5 厂家 A
Node-6 厂家 B 或实验室 B
Node-7 观察/审计方
```

节点必须使用私有 P2P 网络和 allowlist；验证节点密钥放在 KMS/HSM 或等效的受控环境中。厂家可以提交自己的证据，但不能因为拥有业务账户就自动拥有联盟链多数共识权。

### 4.3 Agent、设备和节点的区别

三者不是同一个东西：

- **设备**：产生温度、重量、批次或检测原始观测，并用设备密钥签名；
- **Agent**：调用设备/ERP/LIMS 接口、整理证据、探测服务、运行 JEV 和触发流程；
- **验证节点**：共同维护联盟链账本并参与共识，不负责替设备生成数据。

不要让每台 IoT 设备直接成为区块链验证节点。设备应通过网关或 Agent 提交签名事件，由链下接入层做格式、权限和防重放检查。

### 4.4 链下证据仓

联盟链仍然不能替代原始数据仓。建议使用对象存储加关系数据库：

```text
对象存储：检测 PDF、图片、设备原始文件、视频、报告附件
关系数据库：批次、事件索引、主体、公钥、权限、争议状态
EvidenceEnvelope：把对象 URI、payloadHash、issuer、时间和前序哈希绑定起来
```

链上只写下列字段或其哈希：

- `batchCommitment` / `subjectHash`；
- `evidenceRoot`、`resultHash`；
- `issuerId`、`sourceHash`、`schemaHash`；
- `policyHash`、`verifierVersionHash`；
- 事件时间、序列、状态、撤销和替代关系；
- 联盟链检查点的区块范围和根哈希。

不写入链上的内容：报告全文、图片、连续遥测、消费者姓名/地址、健康信息、API Key、私钥和商业机密。

## 5. 私链和 BOT Chain 如何组合

### 5.1 私链内部记录

联盟链记录高频、低延迟、成员可见的事件承诺：

```text
设备/实验室事件 → 批次事件根 → Verifier 结果 → 争议/替代
```

它适合厂家、实验室和物流方快速对账，也适合在不公开原文的情况下检查“谁在什么时间提交了什么承诺”。

### 5.2 公共锚定检查点

由 TruthPass Anchor Relayer 定期把联盟链的一段事件聚合成 Merkle root 或 checkpoint root，提交到 BOT Chain：

```text
privateChainId
privateBlockFrom
privateBlockTo
checkpointRoot
batchRoot（可选）
schemaHash
policyHash
eventCount
createdAt
```

BOT Chain 上的记录要包含“这是哪条联盟链、哪一段区块、哪一个根”，这样别人才能从公开链回到联盟链索引，再从索引回到链下原文哈希。

当前 `TruthPassEvidenceAnchor` 可以用 `evidenceRoot` 锚定批次根，完成比赛演示；正式生产建议新增明确的 `LedgerCheckpoint` 记录或单独的 checkpoint 合约，避免把“批次证据”和“联盟链检查点”混在同一种语义里。

### 5.3 查询顺序

消费者 Agent 不需要直接连接联盟链验证节点：

1. CLI 查询 TruthPass 公开 API 或 BOT Chain 事件；
2. 如果需要细节，API 根据 `checkpointRoot` 和 `evidenceRoot` 查联盟链索引；
3. 只有获得授权的 Agent 才能访问链下报告原文；
4. CLI 重新计算原文哈希，与联盟链和 BOT Chain 的承诺比对；
5. 任何不一致进入 `review` 或 `disputed`，不能被模型改写成“通过”。

## 6. 什么时候应该建设私链

### P0：比赛和单一试点（现在）

不建设私链。使用当前已经跑通的：

```text
链下 EvidenceEnvelope + 确定性 Verifier + BOT Chain 公共合约
```

目标是把消费者 Agent、CLI、鱼油证据和真实测试网事件讲清楚，减少基础设施故障面。

### P1：多方联调

当至少有两个厂家、一个独立实验室和一个物流/冷链方参与时，再搭建 4 节点 Besu QBFT 开发网：

- 部署与当前合约 ABI 兼容的内部 TruthPass 合约；
- 接入设备/报告签名、公钥注册和撤销；
- 实现联盟链区块到 BOT Chain 的 checkpoint relayer；
- 运行重启、节点掉线、重复事件、错批次和争议回放。

### P2：生产试点

满足以下条件后再做生产网络：

- 验证节点由不同法人或独立组织控制；
- 角色钱包和验证节点密钥分离，并有轮换/吊销流程；
- 原文存储、隐私授权、数据保留和删除请求已有制度；
- 复检、争议 SLA、样品交接和实验室资质已接入；
- checkpoint 可以由公开 BOT Chain 复核，联盟链停机时仍能读取最后一个公开检查点；
- 合约、节点配置、备份和监控完成安全审计。

## 7. 私链建设的验收标准

第一版不以“节点启动”作为完成标准，而以一次完整回放作为完成标准：

1. 三类来源提交同一鱼油批次的生产、实验室和冷链事件；
2. 事件均带有来源签名、批次绑定、时间和前序哈希；
3. JEV 识别缺口，但只有确定性 Verifier 产生最终状态；
4. 联盟链至少 3 个验证节点确认同一批次根；
5. Relayer 把区块范围和 checkpoint root 锚定到 BOT Chain；
6. 消费者 CLI 能从公共链查到检查点，再回到联盟链和链下原文；
7. 篡改报告、替换批次、重放旧事件、节点掉线和争议都进入失败关闭或复核；
8. 旧结果保留，撤销和替代使用追加事件；
9. 网页展示的是这条真实回放链路，而不是静态拼接的数据。

## 8. 对当前项目的明确决策

- **现在已经有的**：BOT Chain Bohr Testnet、`TruthPassEvidenceAnchor`、角色权限、七事件真实回放、链下证据和 CLI/网页观察台；
- **现在没有的**：Besu 联盟链、生产级设备签名、多个组织验证节点、checkpoint relayer、生产密钥隔离和生产数据认证；
- **近期应该做的**：先把当前 BOT Chain 公开配置接入 CLI/网页查询和真实交易状态，再补“联盟链检查点”接口合同；
- **不应该做的**：为了展示多链而先搭一条只有厂家和 TruthPass 两个节点的孤立私链，或把链上事件表述成现实世界的绝对真实性证明。

这条路线让私链成为“多方内部协作和隐私账本”，让 BOT Chain 成为“公共时间戳、公共信誉和跨方复核锚点”，两者职责清楚，消费者只需要使用自己的 Agent/CLI。

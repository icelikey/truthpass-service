# 交流决策沉淀

## 已确定的方向

- 参加赛道一“Agent 公共信誉与服务验收”。
- 以白牌电商作为现实应用场景。
- 首个演示品类使用白牌茶叶或咖啡，优先选择证据结构清晰的茶叶批次。
- 用户角色是品牌方、采购商和采购 Agent；消费者扫码查看证据属于后续展示层。
- 重点流程是陌生服务探测、任务调用、确定性验收、公共反馈和后续查询。
- 物联网在 MVP 中使用带签名的模拟传感器数据，硬件接入保留为扩展点。
- 区块链保存身份、时间、结果和证据哈希，不保存完整商业资料。

## 不纳入首版的内容

- 全品类电商商城；
- 完整硬件物联网系统；
- DAO、代币和复杂支付；
- 跨链；
- 同时完整实现赛题二；
- 只展示静态商品溯源而没有服务调用和履约结果。

## 可复用的既有经验

- 《终焉》的事件流和事实审计可用于验收事件记录；
- 台球项目的 Agent 提议、确定性规则、事件和状态哈希边界可用于验收器；
- 知识库项目的来源登记、证据队列和审核流程可用于服务证据管理；
- 既有网页和叙事能力可用于证据卡、风险解释和比赛演示。

## 2026-10-06 讨论稿新增结论

- 用户自己的语义 Agent 负责理解“我要买蚊香、洗发液或其他商品”；TruthPass 不重复建设通用语义层，而是通过 API、Skill 或兼容接口提供可信商品和服务数据。
- 平台记录的对象包括原材料、生产工序、质检、出厂和交付，但 MVP 只挑一个可结构化验证的品类。
- 第三方检测、平台控制的传感器和监测 Agent 用于交叉认证；区块链只保存身份、时间、结论和证据哈希，不能独立证明现实数据真实。
- 白牌产品的价值主张是透明质量和合理利润，避免只靠品牌溢价或虚假宣传竞争；Agent 可以比较成本、质量和履约记录，但不应替厂商凭空认定“真实价值”。
- 第一版不进入食品、药品等高责任场景。比赛演示可以从白牌充电线或其他小商品开始，因为导通、电阻、温升、耐弯折、批次和出厂记录都容易结构化验收。

## 名称决策

| 层级 | 名称 | 用途 |
|---|---|---|
| 比赛项目 | **真验** | 服务探测、履约验收、公共信誉 |
| 长期应用层 | **OpenGoods 透明货** | 面向消费者的白牌商品透明档案 |

比赛项目正式使用“真验”，英文标识沿用 `TruthPass`；仓库暂时保持 `truthpass-service`，避免把比赛核心误解成完整电商商城。

## 最新 Demo 决策（2026-10-06 鱼油版）

- Demo 场景确定为白牌高浓度鱼油软胶囊批次透明化；核心仍然是服务探测、生产与检测证据验收和公共信誉。
- 鱼油指标使用 EPA+DHA、过氧化值、TOTOX、冷链中断、批次一致性和检测签名，便于现场确定性验收。
- 消费者 Agent 在购买后通过最小授权提交包装、气味、保存和批次可查反馈，参与公共信誉共建。
- 鱼油不做降血脂、预防疾病等医疗功效判断；所有 Demo 数据标记为 `demo/synthetic`。
- 所有演示数据必须标记为 `demo/synthetic`，不能把编造的数据描述成真实供应链证明。
- 原先的燕窝和白牌 Type-C 方案保留为历史讨论，不代表当前 Demo。

鱼油版的具体实现以 [fish-oil-development-plan.md](fish-oil-development-plan.md)、[architecture-v0.3-fish-oil.md](architecture-v0.3-fish-oil.md) 和 [fish-oil-demo-script.md](fish-oil-demo-script.md) 为准。
